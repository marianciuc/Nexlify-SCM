# Задание: Общая структура страниц платформы LogisticCommerce

## Введение

Документ описывает структуру основных корневых страниц платформы LogisticCommerce, их назначение и ключевые функции.
Структура основана на анализе требований из `guidelines.md` и включает предложения по улучшению пользовательского опыта.

все фильтры или любое другое состояние должно рабоать через useSearch() из tanstack

Пока что работаем с плейсхолдерами (создавай отдельные клиенты заглушки в /service/api/clients) согласно правилам
проекта

Sidebar должен быть испольнован готовый из проекта, но его можно дополнять рассширяя функционал если это нужно

---

## Корневые разделы

### 1. /dashboard — Главный хаб

- **Назначение:** Централизованная панель управления для всех ролей.
- **Функции:**
    - Общая статистика по продажам, закупкам, заказам, складам.
    - Быстрый доступ к аналитике, KPI, отчетам.
    - Коммуникация с покупателями и поставщиками (чат, уведомления).
    - Создание и управление аккаунтами персонала.
    - Гибкая навигация ко всем разделам платформы.
    - Реализация drag-and-drop для настройки панели.
    - Уведомления о важных событиях (новые заказы, сообщения, низкий запас).
- **UX-предложения:**
    - Персонализированные виджеты и быстрые действия для разных ролей.

### 2. /store — Магазин заказов

- **Назначение:** Площадка для размещения и обработки заказов между компаниями и поставщиками.
- **Функции:**
    - Размещение заказов, отклики поставщиков.
    - Формирование корзины по рыночной цене.
    - Возможность обсуждения заказа с поставщиком.
    - Просмотр каталога продуктов и поставщиков.
    - Фильтры и сортировка по категориям, рейтингу, цене.
- **UX-предложения:**
    - Интерактивная корзина с расчетом стоимости и сроков.
    - Встроенный чат для обсуждения заказа.

### 3. /warehouse — Управление складами

- **Назначение:** Контроль и аналитика по складам компании.
- **Функции:**
    - Переключение между складами через navbar.
    - История поставок, перемещений, отгрузок.
    - Контроль запасов, автоматические уведомления о низком уровне.
    - Назначение и управление складским персоналом.
    - Быстрый переход к операциям (прием, отгрузка, перемещение).
    - KPI по каждому складу.
- **UX-предложения:**
    - Визуализация движения товаров (диаграммы, карты).

### 4. /setting — Панель настроек пользователя

- **Назначение:** Управление личными и системными настройками.
- **Функции:**
    - Настройки профиля, языка, часового пояса, уведомлений.
    - Безопасность: смена пароля.
    - Интеграции с внешними сервисами.
    - Подсказки и документация прямо в интерфейсе.
- **UX-предложения:**
    - Пошаговые мастера для сложных настроек.
    - Группировка настроек по категориям для быстрого доступа.

## Общие рекомендации по UX (одобрены)

- Использовать статусные индикаторы и прогресс-бары для процессов (верификация, загрузка, обработка заказа).
- Реализовать адаптивный дизайн для мобильных устройств.
- Обеспечить быстрый доступ к справке и поддержке.

## Общие рекомендации по UX (на потом)

- Внедрить систему уведомлений (email, SMS, in-app).

---

## Примечания

- Структура страниц должна учитывать ролевую модель доступа.
- Все разделы должны быть легко расширяемы для новых функций.
- UX-улучшения основаны на best practices из guidelines.md.
